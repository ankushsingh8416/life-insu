# API Reference — Phase 1

Base URL: `http://localhost:4000/api` (via NGINX: `http://localhost/api`)

All REST responses are wrapped: `{ "success": true, "data": T }` or
`{ "success": false, "error": { "code": string, "message": string } }`. Request/response shapes
are defined once in `packages/shared-types` and consumed by both the API and the web app.

## REST

| Method | Path | Body / Query | Description |
|---|---|---|---|
| `GET` | `/health` | — | Postgres + Redis connectivity check |
| `POST` | `/visitors/register` | `{ visitorId?, language? }` | Upsert an anonymous visitor, returns visitor with a stable id |
| `POST` | `/chat/sessions` | `{ visitorId, language? }` | Create a chat session |
| `GET` | `/chat/messages` | `?sessionId=&limit=` | Fetch message history for a session |
| `GET` | `/chat/suggested-questions` | — | Starter questions for the welcome screen |
| `POST` | `/feedback` | `{ messageId, rating: "like"\|"dislike", comment? }` | Upsert feedback on a message |
| `POST` | `/kb/documents/upload` | multipart `file` (pdf/docx/txt/csv, ≤25MB) | Upload a knowledge base source file |
| `POST` | `/kb/documents/url` | `{ url, title?, sourceType? }` | Ingest a web page as a knowledge base source |
| `GET` | `/kb/documents` | `?status=&sourceType=&page=&pageSize=` | Paginated list of knowledge documents |
| `GET` | `/kb/documents/:id` | — | Get one document |
| `DELETE` | `/kb/documents/:id` | — | Delete a document (and its vectors) |
| `POST` | `/kb/documents/:id/reindex` | — | Re-run ingestion for a document |

## Socket.IO (namespace `/chat`)

### Client → server

| Event | Payload | Description |
|---|---|---|
| `chat:join` | `{ sessionId }` | Join a session's room (for reconnects / multi-tab) |
| `chat:send` | `{ sessionId, visitorId, content }` | Send a user message; triggers the RAG pipeline |
| `chat:regenerate` | `{ sessionId, messageId }` | Re-run generation for the exchange that produced `messageId` |

### Server → client

| Event | Payload | Description |
|---|---|---|
| `chat:citations` | `{ sessionId, messageId, citations }` | Sent once retrieval completes, before tokens start |
| `chat:token` | `{ sessionId, messageId, token }` | One streamed token |
| `chat:complete` | `{ sessionId, message }` | Final persisted `ChatMessage` (includes citations, confidence, provider/model, token counts) |
| `chat:rejected` | `{ sessionId, messageId, reason, suggestedQuestions }` | Emitted alongside `chat:complete` when the guardrail declined the query |
| `chat:error` | `{ sessionId, messageId?, message }` | Generation failed (all providers unavailable, or mid-stream failure) |

`messageId` is generated by the server per turn and is stable across `chat:citations` →
`chat:token`(s) → `chat:complete` for that turn, so the client can accumulate tokens into a single
message by id.
